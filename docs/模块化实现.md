# 模块化管理实现

对官方的模块化进行管理和实现，提供更好的模块化开发体验。

之前模板中会自带模块相关的内容，如果模块比较多，会造成比较大的干扰。为了更灵活的管理模块，提供自行打包/安装模块的功能。

## 模块的来源

在`GitHub`上，[Perigon.Modules](https://github.com/AterDev/Perigon.Modules)项目用来存储源代码和模块文件。

其中 `package_modules`中包含已打包的zip文件。

当前仓库中，`modules.json` 位于仓库根目录，包含各个模块的元数据信息。

## 功能说明

- 完善install命令，如果包名是`Perigon.`前缀，则要从github下载官方模块并进行安装。要先判断是否能够正常连接到github.
- install 添加--list(-l) 选项，用来获取官方模块列表。通过`Perigon.Modules`项目中的`modules.json`文件获取。

## 当前实现

### 官方模块列表

支持以下两种方式查看官方模块：

```pwsh
perigon install --list
perigon install list
```

执行时会先请求 `https://api.github.com` 检查网络连通性，然后读取 `Perigon.Modules` 仓库中的 `modules.json` 元数据。

### 官方模块安装

当安装参数带有 `Perigon.` 前缀时，会自动识别为官方模块：

```pwsh
perigon install Perigon.SystemMod AdminService
```

CLI 会从官方仓库的 `package_modules` 目录下载对应 zip 包，然后复用现有本地 zip 安装流程完成模块安装。

### 本地模块安装

原有本地安装方式保持不变：

```pwsh
perigon install ./package_modules/FileManagerMod.zip AdminService
```

## 实现思路

**关于数据获取**
由于数据源在github上，所以获取前都要进行网络连接的判断，比如请求`https://api.github.com`，如果无法连接则提示用户网络异常。

这里涉及到读取(下载)github上仓库的文件，但都是公开项目。当前实现中：

- 使用 GitHub API 检查可用性；
- 使用仓库 tree/blob API 读取 `modules.json`；
- 使用 `raw.githubusercontent.com` 下载 `package_modules` 下的 zip 包。

**关于install命令**
install 是已经存在的命令，并且有对应的参数和选项。当前支持：

- `perigon install list`
- `perigon install --list`
- `perigon install Perigon.<ModuleName> <ServiceName>`
- `perigon install <LocalZipPath> <ServiceName>`
